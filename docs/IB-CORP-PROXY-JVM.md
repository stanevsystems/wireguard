# Записка для ИБ: corp-proxy на VM (JVM)

## Назначение

На гостевой VM нужен **входящий** HTTP-прокси, чтобы рабочая станция host2 ходила в уже разрешённые корп-сайты (`*.inno.local`, `*.vtb.ru` и перечисленные стенды) через сеть гостя. Свой VPN, WireGuard, reverse tunnel и 3proxy на VM не используются.

IntelliJ **Settings → HTTP Proxy** для этого не подходит: это настройка **исходящего** прокси клиента IDE. Слушатель — отдельный процесс разработки `java` / `javaw` с main-class модуля `corp-proxy` (исходники в репозитории, fat JAR).

## Что делает процесс

- Слушает **только** `192.168.136.140:3332` (VMnet), не `0.0.0.0`.
- Принимает `CONNECT host:443`, отвечает `200 Connection Established`, дальше передаёт байты на обычный TCP в сторону корп-маршрута гостя.
- Требует `Proxy-Authorization: Basic`. Пароль лежит в `%USERPROFILE%\.corp-proxy\secrets.local.yaml`, не в git.
- Чужой домен — **403**. IP-литералы в рабочей конфигурации запрещены.
- `GET /health` — проверка живости, без тела запроса к корп-сайтам.
- Пишет access-лог (ротация по размеру), например:  
  `2026-10-20T14:50:00.123Z INFO client=192.168.136.1 CONNECT sfera.inno.local:443 status=200 up=120 down=84000 duration_ms=350`
- Одновременно до 512 соединений. Таймаут TCP к upstream не больше 30 с.

Firewall (одно правило, скрипт `Set-CorpProxyFirewall.ps1`): входящий TCP 3332 только с `192.168.136.0/24` и `10.200.0.0/16`. Служба Windows и задача SYSTEM не создаются. Процесс живёт в сессии пользователя и останавливается командой `--stop` или закрытием проекта, если его поднял плагин IDE.

## Чего процесс не делает

Нет VPN, нет второго сетевого интерфейса, нет разбора TLS (сертификат сайта не подменяется), нет обфускации JAR и нет упаковки «под чужое ПО». Готовые бинарники 3proxy / squid / mitmproxy этим модулем не запускаются: отдельный `3proxy.exe` на этой VM уже давал детект `HackTool.Win64.3Proxy.a`.

## Что просим разрешить

Allowlist для запуска:

- программа: `java.exe` / `javaw.exe` (JDK/JBR, установленный для разработки);
- аргументы вида `-jar <проект>\tools\corp-proxy\corp-proxy.jar --config <проект>\tools\corp-proxy\config.yaml`;
- слушающий порт TCP **3332** на адресе VMnet VM.

Исходники и команда сборки: `corp-proxy/README.md`.
